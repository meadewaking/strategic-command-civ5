# v5 策略审视与实施记录

> 历史设计记录。首次 v5.0 实测失败，接口、目标一致性和生存顺序的修正及当前验证边界见 [v5.1 复盘](STRATEGY_V5_1.md)；以下早期离线通过不能作为实战有效的证据。

日期：2026-09-06。对象：当前安装的 Civilization V BNW、Super Power 5.85_FIN / v6 Beta 与已有战略指挥部。

## 结论与范围

不整体推倒稳定的托管框架。重写它会把弹窗、命令生命周期、城市异步订单等问题重新引入，却不能直接提升战术。保留 V3 事务层和多波次执行器，新增独立的原生战斗预测、纯决策与城市收益模块，替换影响整类行为的旧评分和硬性拦截。

本轮完成两条链路：战场观察到目标选择、执行和结果核对；城市/国库事实到建设、科研收益与生产购买需求。外交、议会、伟人和工人保留已有执行器，不冒充全部重新实现。

这是可测试的改进版本，不是“已证明最优策略”，也不能承诺同等条件下无伤击败游戏 AI。

## 最新样本揭示的问题

当前 Lua.log 来自 v4.0，最后修改于 2026-08-13，并不是新版运行结果。审计包含四个完整托管阶段：

| 策略缺陷 | 旧样本证据 | 本轮响应 |
| --- | --- | --- |
| 指令接受不等于有效执行 | 465 次移动被接受但没有观测到状态效果；436 / 1057 个可机动单位回合有实质动作 | 修正直接任务的 MissionAI 参数；攻击、扫荡和实际伤害分开核对 |
| 火力利用率低 | 734 条局部无目标记录；导弹库存占比约 17.1% | 原生伤害评分、先开火后后勤、按实际射程寻找阵位 |
| 占城跟不上 | 六次占城尝试，仅一次在该采样窗口内确认 | 原生可击杀判断、满血优势占城、1 血占领回归测试、重取存活对象 |
| 低价值生产 | 21 个财富/科研维持订单 | 取消建筑收益截断，使用实际本城收益；阻止旧兵力配额覆盖国家计划 |
| 目标僵化与耗时 | 单次完整托管平均 33.565 秒，最高 41.884 秒 | 无进展目标解锁；每次最多六个复杂阵位搜索 |
| 模型偏离 | 历史 FIDELITY 为 FAIL；原生 Lua 与 Python 对两种反坦克单位分类不一致 | 校验全部数据库单位；回放直接调用部署 Lua，不复制一套评分 |

统计窗口不同不能混用。例如完整玩家阶段内的损失，不包含所有敌方阶段的战损；“命令发送”“状态变化”“伤害确认”也不是同一指标。

## 决策原则

### 战争与闪击

1. 只对当前战争对象发起攻击；移动不得通过自动确认弹窗扩大战争。单位目标需要当前可见且没有对我方隐形，战略城市目标限于已经揭示的位置。
2. 先执行已经可用的火力和占城机会，再治疗、运输、换基地、机动。移动后重新读取战场，最多继续三波火力与占领。
3. 战斗不是比较两张卡片上的战斗力。以原生预测伤害和反击为输入，比较消除的敌方价值、自身损失、敌方火力威胁及弹药代价。
4. 非一次性单位若预期反击加 25% 不确定性余量可能致死，拒绝该攻击。伤兵的无反击远程火力不因统一血量阈值被禁用。
5. 远程单位停止攻击 1 血城市；近战仍可占领。无法单击拿城时，只有附近可行动支援的预测总伤害足够，才允许收益合适的非致命近战攻城。
6. 一次性导弹比较目标价值和自身造价。优先消除有威胁单位，不向几乎没有剩余价值的廉价残兵倾倒昂贵弹药。
7. 国家计划只提供方向，不压掉眼前机会。有明显局部优势及占领力量时保持进攻，而不是因另一战区承压全军退守。
8. 目标连续三回合没有接近、压血或削弱守军，取消锁定加分并重新竞争。保持有进展的行动连续性，但不再给予压倒所有新机会的绝对锁定。

### 海空与运输

- 护航舰先移动，航母、弹道导弹潜艇和高价值武库平台后移动。排序是协调的必要条件，不等于已经建立完整编队寻路。
- 普通火力平台的阵位距离不得超出实时射程；航母平台根据实际搭载机的射程选择工作距离。
- 基地危险由附近已知敌军的原生伤害、距离和域适用性估计。少数落后敌军靠近不会自动触发整支舰载航空队撤离。
- 制空扫荡要求有原生活跃拦截者，不仅依据地图上出现一架敌机；防空单位也纳入候选。
- 保留现有军事基地空运、护送运输和登陆模块。海路可达性、海峡、登陆空间和下一敌方回合的真实集火仍需实战验证；不把六角距离冒充完整路径证明。

### 城市、国库与扩军

- 比较实际边际收益：平产出、按人口产出、基础产出的百分比，以及本城正在工作的资源/地形/地貌和实际专家数量。数据库存在某资源，并不代表每座城市都受益。
- 扣维护费并折算生产等待时间。购买立即获得建筑，不应用建造数十回合的折扣。连续购买候选会刷新本城经济缓存。
- 占领不满的法院、低幸福时的幸福建筑、战时空运设施与资源缺口有明确效用加分。
- 赤字不是立即破产。保留战时八回合、和平十二回合的消耗储备，并考虑运营成本；国库仍能长期支撑时允许利用资金优势。
- 普通扩军与额外资本扩军共同依据国家编成和战区兵力。取消“有两次行动就至少要 110 个单位”这类独立配额，也不再采用总和超过 100% 的额外兵种份额。
- 下游生产和购买必须接受“该兵种没有缺口”的结果，不回退到另一套旧配额。沿海、飞机、占领力量和支援力量仍使用既有统一需求类别。
- 精英单位及其前置项目仍由原项目机制生成候选；不修改属性、不免费生成单位。研究中的项目锁定兵种会折价，不能把研究完成误当成马上获得精英兵。
- 精英候选也必须填补当前兵种缺口，或相对该兵种现有最佳力量提供明显代差；队列中的力量算入供给。仅仅贴着“精英”标签，不再绕过编成重复征募。资金即将枯竭时先恢复经济，受直接威胁的城市不能先开长期精英项目或征募工人。
- 没有即时军事威胁的城市，在占领不满、幸福危机或资金危机时，优先建设实际能缓解该问题的建筑，再考虑精英和其他常规项目。

### 科研、政策和长期发展

- 科研不再因英文名称包含军事关键词而获得巨额固定加分。依据可解锁内容、已有缺口、原生 Flavor 和完成时间比较。
- 过滤其他文明专属替代单位/建筑，避免某项科技因为包含大量不能生产的独特单位而虚高；保留后续科技依赖链的折扣收益。
- 政策额外计入本国实际拥有的建筑类别和城市数量所产生的收益，保留意识形态和可选性检查。
- 本游戏是文明 V，不存在文明 VI 的区域、住房和政策卡槽。本轮没有以不存在的接口实现这些概念。
- 工人、移民、贸易、伟人、宗教、间谍与议会仍走已有模块。它们的原有规则尚不等同于完整长期胜利规划，后续应使用独立样本改进，不能因战争测试通过就认为发展策略正确。

## 各类单位的职责

以下是统一职责约束，不表示每个类别都有新增的独立完整 AI。类型来自实际单位表及固有晋升，实时射程、行动力、最大血量和禁止占领标志覆盖静态缓存。

| 类别 | 操纵原则 |
| --- | --- |
| 主战坦克、骑兵、快速突破单位 | 跟进火力、接近缺口、收尾占城，避免先冲进未清理火力区 |
| 普通近战、防线和反制单位 | 控制通路、保护己方火力，反坦克部队不因名字含 TANK 被当成主战坦克 |
| 侦察、空降、直升机 | 侦察及机动侧翼；占领能力以实际能力与原生任务合法性为准 |
| 陆上远程、攻城炮 | 在真实射程内先开火，再考虑移动与治疗，避免反复寻找超射程“安全阵位” |
| 末日机甲 | 尊重本机安装的特殊击杀脚本；对另一末日机甲不能套用秒杀规则 |
| 防空、护航、驱逐舰 | 屏护、反潜和必要的沿海占领；拥有远程副武器时也参与火力决策 |
| 攻击潜艇、水面火力和武库舰 | 打击可触及的高价值舰船/登陆威胁；长程平台不承担前导任务 |
| 航母与弹道导弹潜艇 | 保持有效放飞机/导弹的位置，重视自身及搭载资产，不抢护航舰的先导顺序 |
| 制空、舰载多用途和轰炸机 | 按拦截风险、预期损失及目标价值使用扫荡/攻击，先利用当前基地的火力 |
| 常规导弹、核武及特殊炮 | 常规消耗品核算交换收益；核武和特殊武器保留专用授权/执行层，不从普通目标评分绕过 |
| 工人、移民、贸易、宗教、伟人、飞船部件 | 使用相应专职模块，不因维护回合流程而混入普通战斗或占领任务 |

在 Mod 目录运行：

```powershell
& 'C:\Program Files (x86)\Lua\5.1\lua.exe' Tools/DecisionTests.lua .
python Tools/DecisionReplay.py --self-test --log "$env:USERPROFILE\Documents\My Games\Sid Meier's Civilization 5\Logs\Lua.log"
python Tools/CatalogContract.py --bootstrap "$env:USERPROFILE\Documents\文明mod\StrategicCommand_OfflineSmoke.lua"
```

工作区的 `Run-StrategicCommandTests.ps1` 统一运行上述检查、Lua 语法、清单 MD5、托管冒烟、城市事务、执行世界和历史回归。冒烟中的 `expected smoke failure` 是故意测试模块异常隔离，不是游戏报错。

本轮自检：51 条实际 Lua 决策断言覆盖战斗、财政、精英缺口/代差和紧急建设；另有 283 个数据库单位的真实分类器检查，以及 40 个移动候选的六次复杂搜索与失败回退测试。两个版本警告来自旧日志仍为 v4.0，历史 FIDELITY 仍为 FAIL，新版事实回放为 INSUFFICIENT_DATA。这些状态刻意保留，不能当成 v5 实战通过。

新增日志：

- `decision5 candidate / selection`：前几个合法攻击候选、原生事实、分数、排除原因汇总。
- `decision5 attack / outcome`：攻击前的预期与立即可观察的实际伤害/损失。`confirmed=false` 代表尚未确认，不等于已打中，也不一定是最终失败。
- `decision5 buildings`：本城前三个建设候选、收益、时间与最终选择。
- `decision5 finance / movement / operation`：资金可支撑回合、搜索范围、无可行阵位或无进展的原因。

回放器使用受限键值解析，不把日志文本当代码执行。只记录前三个攻击候选，不保存全部被原生规则否决的候选快照。不能据此声称已完整记录游戏内部状态或操作系统全部键鼠输入。

## 原生规则依据与模型边界

实际适配以本地 `EnemyUnitPanel.lua` 的战斗预览调用、`NewCombatRules.lua` 的机甲特效/占领恢复以及当前 `Civ5DebugDatabase.db` 为准。参考 [DLL-VMC 原生战术流程](https://github.com/whoward69/DLL-VMC/blob/master/CvGameCoreDLL_Expansion2/CvTacticalAI.cpp) 和 [Lua 单位绑定](https://github.com/whoward69/DLL-VMC/blob/master/CvGameCoreDLL_Expansion2/Lua/CvLuaUnit.cpp) 核对接口；参考源码不意味着当前二进制与该仓库完全相同。

- 直接任务的 MissionAI 参数不是再次传 MissionType；使用 `-1`，不传攻击者本身作为目标单位。
- `GeneratePath` 的 Lua 绑定并未实现，不能当作路径模拟器。
- 当前参考绑定未暴露拦截伤害预测，因此拦截采用明确标记的 25 点生存不确定性余量，而不是调用不存在的方法。该余量只进入生存门槛，不冒充每次必然承受的经济损失，以免昂贵先进飞机拒绝攻击落后敌人。这不是精确空战公式。
- 原生伤害预测不覆盖所有随机结果、模组连锁伤害、敌方集火及地图通路。下一轮最重要的是比较这些预测与真实结果，而不是继续扩大一个自行编写的“理想世界”。

## 最小实战观察

只需一次重启，使用原存档托管五回合，保留 Lua.log：

1. 日志开头确认加载 `v5.0`。记录仍需手动处理的窗口及大致回合即可，不要求逐个重复测试旧功能。
2. 观察已在射程内的飞机、导弹和舰炮是否先攻击；有占领单位的空血城市是否及时易主，优势机甲是否仍无故等城残血。
3. 观察航母是否抢先冲锋，陆军运输是否继续卡在同一海格；这两项需要真实寻路样本才能判断。
4. 观察富裕国家是否补缺兵种、购买有实际收益的建筑；再看每回合耗时是否下降，是否出现单位损失或卡住。

若仍差，下一阶段优先按原生伤害误差、失败落点和基地风险做校准，再完善登陆/编队路径及生产机会成本。不要用同一份旧日志反复证明新版有效。
