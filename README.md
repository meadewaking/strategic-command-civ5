# 战略指挥部 / Strategic Command

《Sid Meier's Civilization V》后期高层托管与微操减负 Mod。

这个项目是为后期大帝国、大规模战争和 Super Power Clash of Civilizations 类玩法制作的自动化层。目标不是替玩家“完美代打”，而是把大量低价值重复操作交给脚本处理，让玩家只需要每隔若干回合做一次战略层面的干预。

当前版本：`v5.1`
状态：`Alpha`
支持：单人游戏
不支持：多人、热座

## 核心目标

后期 Civilization V 经常会被以下操作拖慢：

- 每回合大量单位需要命令。
- 城市生产队列反复需要补。
- 科技、政策、意识形态、宗教、考古等弹窗不断打断。
- AI 外交、世界议会、伟人诞生和奇观通知需要玩家频繁点击。
- 战争中远程单位、城市炮击、伤兵、舰队和空军都需要重复微操。

战略指挥部试图把这些低层操作封装成“托管若干回合”的模式：玩家先选择外交、经济、建设、生产、战争等倾向，然后指定接管 `5 / 10 / 20 / 50` 回合。

## v5.1 战损复盘与修复

v5.0 实测未通过：占城/机动链路发生 36 次模块异常，98 次攻击存在候选与下令前事实不一致；仅检查评分复现曾误报正常。v5.1 修复跨模块接口、统一原生防御目标，增加开火前撤离、危险基地疏散、离子炮连锁收益和关键军事异常停托管。详见 [v5.1 战损与验证记录](Docs/STRATEGY_V5_1.md)。

本版离线测试不是实战胜率证明，也不是完整 Civ5 引擎模拟。

## v5 原生预测与实际收益

这次保留已有托管、UI 和异步订单框架，更新战斗决策及城市经济决策。完整依据、规则、局限与最小测试见 [v5 策略审视与实施记录](Docs/STRATEGY_V5.md)。

- 战斗使用游戏原生伤害预览，比较有效伤害、反击损失、目标威胁和一次性弹药成本；不再仅按单位名称和基础战力排队。
- 占城按真实可造成的伤害判断，允许优势单位直接攻取满血城；1 血城停止轰炸，但仍允许近战占领。
- 先处理危急撤离和基地疏散，再使用可执行火力、普通治疗、换基地和运输；护卫先移动，航母后移动；射击阵位跟随单位实际射程。
- 建筑按本城基础产出、已工作的地块、人口、维护费和完成时间评估。购买不再套用生产等待时间。
- 资金危机依据国库能支撑多少回合判断；生产与购买共享国家需求，避免下游旧配额反复扩军。
- 作战目标连续三回合没有接近、压血或削弱守军，就取消锁定加分；复杂阵位搜索每单位每次最多处理六个高优先级目标。
- 离线测试执行部署的 Lua；数据库分类与旧模拟器交叉检查；`decision5` 日志可回放原始评分。

**验证边界：**离线通过不等于实战通过。旧版模拟器的“消灭全部敌军”等结果只是简化场景，不代表本版已在游戏中实现。v5.0 实测回放现为 `FAIL`，v5.1 尚需游戏运行采样；不能把历史评分吻合当成新版实战通过。

## v4 执行优先架构

v4 把“国家计划”和“战场执行”拆成两个不同权限层：国家计划只给城市目标、编组和生产方向加分，不能再禁止单位攻击眼前敌人、向前线移动或补位占城。军事执行每轮按“先手火力 -> 占城 -> 机动 -> 刷新战场 -> 再开火 -> 再占城”运行最多三波，直到没有有效动作。

- `StrategicCommand_ExecutionWorld.lua`：只保存敌方单位/城市的 ID 与坐标；战斗后失效并重建，不跨阶段持有原生对象。
- `StrategicCommand_ExecutionMilitary.lua`：多波次军事执行器，移动、火力和占城形成闭环。
- 移动失败不再算作完成，并在本回合排除失败落点后选择替代方案。
- 占城分配只是优先权；任何可执行占领单位都可以补位拿下空血城市。
- 保守路点搜索失败时退回游戏原生寻路，不再让整支远征军原地空转。

## v3 稳定性模块

v3 停用了旧版巨型编排器和重复的回合驱动，托管流程现在只有一个入口，并拆分为五个职责明确的模块：

- `StrategicCommand_V3_State.lua`：回合状态、事务和模块隔离。
- `StrategicCommand_V3_City.lua`：城市异步订单的提交、确认、超时与重试。
- `StrategicCommand_V3_Blockers.lua`：科研、生产、晋升、单位命令和议会阻塞器收敛。
- `StrategicCommand_V3_SpecialWeapons.lua`：粒子炮等高影响武器的先手目标选择。
- `StrategicCommand_V3_Military.lua`：准备、后勤、开火、机动、扩大战果和收尾阶段。
- `StrategicCommand_V3_Engine.lua`：唯一的全量/轻量托管入口。

旧主文件仍包含 Civ V 事件接入、UI、命令适配和部分历史策略逻辑；并未完成彻底拆分。托管顺序由独立执行器决定，轻量弹窗回调只处理当前阻塞，不再重新扫描全国城市和全军。

## 已实现功能

### 托管面板

- 游戏内左上角显示“战略”按钮。
- 可启动 `5`、`10`、`20`、`50` 回合托管。
- 可手动执行一次完整托管流程。
- 可停止托管。
- 面板内可选择多类战略预设。
- UI 文本使用中文。

### 战略预设

目前包含以下预设维度：

- 外交：均衡、友好、强硬、孤立。
- 经济：均衡、科研、财政、扩张。
- 建设：基建、幸福、科研、防御。
- 开发：自动、产能、铁路、保守。
- 生产：建筑、军队、海空、奇观。
- 战争：防守、推进、总攻、海权。
- 占城：傀儡、智能、吞并、焚城。
- 伟人：保留、科研、工程、文化。
- 宗教：产能、科研、金币、文化。
- 贸易：均衡、金币、科研、内运。
- 间谍：反谍、窃技、城邦、外交。

这些预设会影响自动科研、生产评分、战争行动、伤兵阈值、战术行动次数、海军/空军倾向等行为。

### 城市与生产

- 国库、收入与幸福度充裕时，自动按人口、产能、前线距离和海军价值选择性吞并傀儡城。
- 吞并后优先购买法院、军事基地、产能和高边际收益建筑；每城每轮只提交一次异步购买，避免消息队列冲突。
- 自动为非傀儡、非抵抗城市补充生产队列。
- 支持把城市队列补到目标长度。
- 根据战争状态、城市位置、建筑类型、维护费和战略预设评分。
- 避免同一轮给同一城市重复塞入同一个建筑/单位。
- 可选择偏建筑、偏军队、偏海空或偏奇观。
- 可处理城市炮击。

### 科技、政策与意识形态

- 自动选择科研。
- 自动选择社会政策。
- 自动处理意识形态选择。
- 自动处理免费政策/政策通知。
- 科研、工业、战争等倾向会影响选择优先级。

### 单位控制

- 自动升级单位。
- 自动选择单位晋升。
- 自动治疗伤兵。
- 自动处理需要命令的单位。
- 自动处理堆叠单位，让单位尝试离开非法堆叠格。
- 自动执行城市炮击和远程单位射击。
- 对空军、导弹、海军、陆地远程单位设置不同的每回合战术行动上限。
- 对没有有效目标、没有安全路径、目标超出范围、行动失败等情况记录原因。
- 从当前激活的游戏数据库读取单位战斗类型、默认 AI、射程、移动力、载荷和初始晋升能力，并自动归入制空、舰载多用途、打击机、导弹、航母、弹道导弹潜艇、攻击潜艇、防空屏卫、舰炮支援、突击舰、炮兵、机动防空、装甲突破、反装甲、防御、侦察、空降等战术类别。
- 作战按制空/屏卫、纵深打击、远程压制、突击收城的顺序执行；同一战区共享进攻焦点，优先歼灭城市周边敌军，再压低城防并由具备占领能力的单位收城。
- 航母、武库舰和弹道导弹潜艇保持安全距离；屏卫舰与机动防空优先保护高价值单位；受损高价值单位更早撤退。
- 炮兵会先架设再射击，战斗机可执行空中扫荡，空降单位寻找安全着陆区，多次攻击单位可以在同一回合继续执行有效行动。
- 远洋运输采用编队推进：威胁区内护航不足时停船，护航舰先占据下一航点后运输单位才前进。

### 弹窗与通知

托管时会尝试自动处理或关闭以下干预项：

- 占领城市后的处置弹窗。
- 伟人诞生与免费伟人选择。
- 科技完成提示。
- 政策与意识形态提示。
- 宗教、万神殿、考古相关弹窗。
- 世界议会提案与投票。
- 外交领袖打断。
- 部分奇观、通知和低价值提示。

### 自动结束回合

- 托管期间会在阻塞项清理后自动结束回合。
- 发送结束回合后进入“转场静默模式”，避免在 AI 回合切换阶段继续重复下命令。
- 如果仍有阻塞，日志会记录阻塞类型和处理尝试。

### 日志与调试

Mod 会输出带有 `[Strategic Command][SCDBG]` 的详细日志，用于迭代策略质量。

日志覆盖：

- 每次托管 pass 的开始与结束。
- 城市生产候选、分数、选择和保留项。
- 单位行动、目标选择、射击结果、失败原因。
- 单位晋升、升级、治疗、最终命令。
- 弹窗、通知和玩家鼠标/键盘输入审计。
- 自动结束回合、阻塞项、重复发送保护。

仓库还包含本地辅助脚本：

- `Collect-StrategicCommandLog.ps1`：收集并归纳最新 Lua 日志。
- `Run-StrategicCommandTests.ps1`：运行 Lua 语法、静态契约和离线 smoke test。
- `StrategicCommand_OfflineSmoke.lua`：离线加载 smoke test。
- `Tools/StrategySimulator.py`：读取实际 `Civ5DebugDatabase.db` 和游戏日志。无日志时只运行分支/算术契约；传入日志后会重建托管前后的真实单位状态，统计有效行动、空转、最终命令、占城转化和战损，并检查离线结果是否过度乐观。

## 安装

把仓库目录放到 Civ5 Mod 目录中：

```text
Documents\My Games\Sid Meier's Civilization 5\MODS\Strategic Command (v 1)
```

目录结构应类似：

```text
Strategic Command (v 1)
├─ Strategic Command (v 1).modinfo
├─ Lua
│  ├─ StrategicCommand.lua
│  ├─ StrategicCommand.xml
│  └─ StrategicCommand_Config.lua
└─ Docs
   └─ README.txt
```

进入游戏后：

1. 主菜单选择 Mods。
2. 勾选“战略指挥部”。
3. 载入或开始一局单人游戏。
4. 进入游戏后点击左上角“战略”按钮。

## 使用建议

推荐先用较短托管测试：

1. 选择预设。
2. 点击 `5回合` 或 `10回合`。
3. 观察是否还有弹窗、单位或城市生产需要人工干预。
4. 如果出现卡住、闪退或行为明显低效，退出后检查 Lua 日志。

战争场景建议：

- 陆战推进：战争设为“推进”或“总攻”。
- 海军远征：生产设为“海空”，战争设为“海权”。
- 防守消耗：战争设为“防守”，建设设为“防御”。

和平发展建议：

- 科研冲刺：经济设为“科研”，建设设为“科研”。
- 大规模基建：建设设为“基建”，生产设为“建筑”。
- 缺幸福：建设设为“幸福”。
- 缺钱：经济设为“财政”，贸易设为“金币”。

## 配置

主要配置文件：

```text
Lua\StrategicCommand_Config.lua
```

常用开关：

- `AutoCityProduction`：自动城市生产。
- `AutoElitePrograms`：自动争夺精英工程并补造解锁单位。
- `MaxQueuedEliteProjects`：帝国同时排队的精英工程上限。
- `EliteUnitTargetPerType`：每类精英单位的目标数量。
- `AllowMechEliteProduction`：是否允许自动生产末日机甲，默认关闭。
- `AutoResearch`：自动科研。
- `AutoPolicy`：自动政策。
- `AutoPromoteUnits`：自动晋升。
- `AutoStrategicMove`：自动战略机动。
- `AutoPopupHandling`：自动弹窗处理。
- `AutoEndTurn`：自动结束回合。
- `DebugLogging`：调试日志。
- `DebugUnitCommands`：单位命令日志。
- `DebugCityProduction`：城市生产评分日志。

一般不需要手动改配置；游戏内预设会覆盖大部分策略参数。

## 开发与验证

在 PowerShell 中运行：

```powershell
powershell -ExecutionPolicy Bypass -File "C:\Users\meade\Documents\文明mod\Run-StrategicCommandTests.ps1" -SkipLog
```

也可以单独运行数据库驱动的策略契约检查：

```powershell
python "Tools\StrategySimulator.py" --json
```

传入 `--log "...\StrategicCommand_SCDBG_latest.log"` 时，会启用实战执行回放。它不把“选中一个策略分支”当作行动成功，而是根据 `pass-begin` 完整快照和 `pass-end` 状态变化确认单位是否真的移动、开火、撤退、晋升或占城。

```powershell
python "Tools\StrategySimulator.py" --log "C:\Users\meade\Documents\文明mod\StrategicCommand_SCDBG_latest.log" --strict-realism
```

`--strict-realism` 会在实战行动覆盖、占城转化或精锐生存明显违背离线契约时返回失败。手写场景现在标记为 `CONTRACT`，只证明规则分支和算术成立，不再被描述为游戏表现预测。

收集最新日志：

```powershell
powershell -ExecutionPolicy Bypass -File "C:\Users\meade\Documents\文明mod\Collect-StrategicCommandLog.ps1"
```

日志收集脚本会同时更新 `StrategicCommand_strategy_audit_current.json`，其中的 `execution_replay` 和 `fidelity_report` 可直接用于下一轮策略迭代。

## 已知限制

- 这是 Alpha 阶段，策略质量仍在迭代。
- Civ5 Lua API 对某些 UI 弹窗和单位命令没有稳定公开接口，部分行为需要通过 UI/Network fallback 处理。
- 自动军事行动仍需要继续优化，尤其是航母、舰载机、导弹、远洋舰队和复杂攻城链路。
- 托管目标是减少微操，不保证每一步都优于玩家手动操作。
- 大型整合包中的其他规则脚本可能影响回合结束、战斗结算或 AI 回合稳定性。

## 项目方向

后续重点：

- v2.7 根据 T216-T223 战役日志重做集中闪击链：数量劣势时只保留一条主攻轴，通常最多两条；既有目标锁定八回合，近期兵力回撤达到阈值时转入防御。占城任务只接受当前作战轴或近距机会目标，禁止从其他战区抽调占领者。巨额国库按赤字可支撑回合数判断可用资金，危机中仍会受控吞并傀儡城、优先购买法院/幸福/经济建筑并按缺编快速购军。
- v2.9 根据 T211-T214 实战日志修复联合作战链：有足够护航的海运陆军会继续前进并主动寻找登陆点，只有护航不足时才停船；空军和导弹按自身实际射程补全已发现目标，战略预备队会向主要战区前推；防御编组不再过量征用攻城、空中和舰炮火力。城市生产改为每城每轮只提交一个异步命令，避免建筑选择被后续财富项目覆盖，并把默认预排队缩短到两项。
- v2.8 根据 T230-T235 实战日志重做攻防编组与军备规划：城市守备不再征用航母、舰载机、战略潜艇和导弹，主攻轴优先获得占城、制空、对地和远程火力；各兵种槽位设独立上限，避免近海舰填满整支作战群。扩军目标改用当前战区威胁而非全球敌军总量，并限制同型号、同兵种的单回合重复生产和购买。新增真实阵亡事件统计，补员不再掩盖战损；购军候选目录改为每回合构建一次以缩短决策时间。
